用 new-api 当中转站，最容易被绕晕的就是**倍率**：

- 模型倍率、分组倍率、补全倍率、缓存倍率——四个倍率叠在一起，到底怎么算？
- 后台余额显示几百万，那是多少钱？
- 500,000 这个数字哪来的？
- Kiro 这种订阅制渠道没有官方 token 价，倍率怎么定？

这篇番外把这套体系从类比到算例完整讲一遍。看完你应该能自己给任何渠道定倍率，并算清每一次调用扣了多少钱。

## 一、先用打车类比建立直觉

调用模型计费，和**打车**的结构一模一样：

```
打车费 = 里程 × 每公里单价 × 车型系数 × 会员折扣
模型费 = token数 × 基础单价   × 模型倍率   × 分组倍率
```

一一对应：

| 打车 | new-api | 含义 |
|------|---------|------|
| 里程 | token 数 | 你用了多少 |
| 每公里单价 | 基准价 $2/1M tokens | 全系统统一的"起步标准" |
| 车型系数（快车 1.0 / 专车 2.0 / 豪华 4.0） | **模型倍率** | 用什么模型 |
| 会员折扣（金卡 8 折） | **分组倍率** | 你是谁 |
| 高速费另算 | **补全倍率** | 输出 token 比输入贵，单独加价 |

记住这张表，后面所有概念都是它的展开。

## 二、核心公式

一次请求扣的 quota（new-api 源码 `service/quota.go`）：

```
quota = (输入tokens + 输出tokens × 补全倍率) × 模型倍率 × 分组倍率
```

如果有缓存命中，再加一项：

```
quota = (输入tokens + 缓存命中tokens × 缓存倍率 + 输出tokens × 补全倍率) × 模型倍率 × 分组倍率
```

**记忆口诀**：

> 输入输出先折算，模型分组再连乘，除以 50 万是美元。

## 三、quota 是什么？500,000 是哪来的？

### 1. quota 是 new-api 的内部记账单位

后台看到的"余额 5,000,000"不是美元，是 quota。它和美元的汇率写死在源码里：

```go
// common/constants.go
var QuotaPerUnit = 500 * 1000.0  // $0.002 / 1K tokens
```

即 **1 USD = 500,000 quota**。

### 2. 500,000 的推导

one-api（new-api 前身）作者当年定了一个基准价：

> **1000 个 token = $0.002**（即 1M tokens = $2）

那么 1 个 token 值：

```
1 token = $0.002 ÷ 1000 = $0.000002（两百万分之一美元）
```

这个数太小，直接用美元记账全是浮点小数。于是反过来定"1 美元等于多少 quota"：

```
1 USD ÷ $0.000002/token = 500,000 quota
```

**500,000 就是基准价 $2/1M 的倒数形式。**

### 3. 一个巧妙的巧合

因为基准价是 1M tokens = $2，而 1 USD = 500,000 quota，所以：

```
1 USD = 500,000 quota = 500,000 个基准 token
→ 1 quota = 1 个基准模型的 token
```

这就是为什么计费公式那么干净：`token 数 × 模型倍率` 直接等于 quota，不用乘任何系数。

### 4. 验证

gpt-4o（官方输入 $2.5/1M，模型倍率 1.25）调 1M tokens：

```
quota = 1,000,000 × 1.25 × 1.0 = 1,250,000
换美元 = 1,250,000 ÷ 500,000 = $2.5  ✓ 正好等于官方价
```

> ⚠️ `QuotaPerUnit` 技术上可以改，有些商业中转站改成 100,000（"1 元 = 10 万 quota"方便用户理解）。**自用千万别改**——改了整套倍率体系的换算基准全乱。

## 四、模型倍率：怎么算出来的？

### 1. 计算公式

```
模型倍率 = 官方输入价（$/1M tokens）÷ 2
```

那个"2"就是基准价 $2/1M——所有模型都表达成"是基准模型的几倍价"。

### 2. 用源码默认表验证

`setting/ratio_setting/model_ratio.go` 里的每一行都符合这个公式：

| 模型 | 官方输入价 | 计算 | 源码倍率 | ✓ |
|------|-----------:|------|--------:|---|
| gpt-4o | $2.5/1M | 2.5 ÷ 2 | 1.25 | ✓ |
| gpt-4.1 | $2/1M | 2 ÷ 2 | 1.0 | ✓ |
| gpt-4.1-mini | $0.4/1M | 0.4 ÷ 2 | 0.2 | ✓ |
| claude-3-haiku | $0.25/1M | 0.25 ÷ 2 | 0.125 | ✓ |
| claude-sonnet-4.5 | $3/1M | 3 ÷ 2 | 1.5 | ✓ |
| claude-opus-4.x | $5/1M | 5 ÷ 2 | 2.5 | ✓ |
| gpt-4 | $30/1M | 30 ÷ 2 | 15 | ✓ |
| gpt-4-32k | $60/1M | 60 ÷ 2 | 30 | ✓ |

源码注释里甚至直接写着对应价格：

```go
"gpt-4o":              1.25, // $2.5 / 1M tokens
"claude-sonnet-4-5":  1.5,  // $3 / 1M tokens
```

### 3. 为什么用"输入价"而不是输出价？

因为输出价由**补全倍率**单独管。定价被拆成两个独立维度：

```
模型倍率 = 输入价 ÷ 2        → 管"输入 token 多贵"
补全倍率 = 输出价 ÷ 输入价    → 管"输出比输入贵几倍"
```

以 claude-sonnet 为例（输入 $3/1M，输出 $15/1M）：

```
模型倍率 = 3 ÷ 2 = 1.5
补全倍率 = 15 ÷ 3 = 5
```

验算 1M 输入 + 1M 输出：

```
new-api：(1,000,000 + 1,000,000 × 5) × 1.5 = 9,000,000 quota = $18
官方价：$3 + $15 = $18  ✓
```

## 五、补全倍率：输出为什么要单独算？

因为官方定价里**输出就是比输入贵 3~5 倍**：

| 模型 | 输入价 | 输出价 | 补全倍率 |
|------|-------:|-------:|--------:|
| claude-sonnet | $3/1M | $15/1M | 5 |
| gpt-4o | $2.5/1M | $10/1M | 4 |

new-api 不记两个价，而是说"**输出的每个 token 按 N 个输入 token 折算**"。

**算例**：调 claude-sonnet，输入 1000 tokens、输出 200 tokens：

```
① 输出折算：200 × 5 = 1000（等价输入 token）
② 合计：1000 + 1000 = 2000
③ 乘模型倍率：2000 × 1.5 = 3000 quota
④ 换美元：3000 ÷ 500,000 = $0.006

验算官方价：1000×$3/1M + 200×$15/1M = $0.003 + $0.003 = $0.006 ✓
```

## 六、分组倍率：运营者的定价杠杆

前两个倍率由**上游官方价**决定，你没得选。分组倍率才是**你自己定的**——它回答"谁在用"。

### 1. 典型配置

| 分组 | 倍率 | 用途 |
|------|-----:|------|
| default | 1.0 | 按标准价 |
| vip | 0.8 | 优质用户 8 折 |
| intern | 0.5 | 实习生配额消耗减半 |

### 2. 算例：同样的调用，不同的人

三个用户都调 claude-sonnet，都是 1000 输入 + 200 输出（前面算出基础 3000 quota）：

| 用户 | 分组 | 分组倍率 | 实扣 quota | 美元 |
|------|------|--------:|----------:|-----:|
| 张三 | default | 1.0 | 3000 | $0.006 |
| 李四 | vip | 0.8 | 2400 | $0.0048 |
| 王五 | intern | 0.5 | 1500 | $0.003 |

**模型倍率管"用什么"，分组倍率管"谁在用"。**

### 3. 运营用法：价格信号

分组倍率本质是**引导用户行为的杠杆**：

- Kiro 渠道边际成本近零 → 建 `kiro-group` 设 0.3 倍率，用户余额消耗慢，自然优先用
- OpenAI 按量 API 是真金白银 → 走该渠道的分组设 1.2，覆盖服务器成本

还有更精细的**用户组-渠道组交叉倍率**（源码 `GetGroupGroupRatio`）：可以配"研发组走 Kiro 按 0.3 扣，走 OpenAI 按 1.2 扣"。

## 七、缓存倍率：为什么粘性路由能省钱

命中 prompt 缓存的输入 token 按**缓存倍率**（通常 0.1~0.5）计费——这是官方给的缓存折扣（Claude 缓存读是输入价的 1/10）。

**算例**：调 claude-sonnet，输入 3000 tokens（其中 1000 命中缓存，缓存倍率 0.1），输出 500：

```
① 未缓存输入：2000 × 1.0 = 2000
② 缓存输入：  1000 × 0.1 = 100     ← 打 1 折
③ 输出折算：  500 × 5 = 2500
④ 合计：4600
⑤ 乘模型倍率 1.5 × 分组倍率 1.0：6900 quota = $0.0138

对比无缓存：(3000 + 2500) × 1.5 = 8250 quota = $0.0165
省：16%
```

这就是为什么第 8 篇强调**渠道亲和性（粘性路由）**——同账号连续会话缓存命中率高，实际成本能降 20~50%。

## 八、订阅制渠道怎么定倍率？（Kiro 实例）

Kiro Pro 是 $20/月随便用，**没有官方 token 价**，公式里的"官方输入价"从哪来？

### 方法：摊销成等效 token 价

**第一步：月费 → 每 1M tokens 成本**

```
每 1M 成本 = 月费 ÷ 每月用量（以 1M 为单位）
```

假设一个 Kiro Pro 账号每月能跑 2000 万 tokens（= 20 个 1M）：

```
摊销成本 = $20 ÷ 20 = $1/1M
```

**类比**：¥200/月的健身卡，一个月去 20 次，单次成本 ¥10——健身卡没有单次价，摊销后就有了。

**第二步：套通用公式**

```
模型倍率 = 1 ÷ 2 = 0.5
```

### 关键：分母决定一切

链条里 $20 是确定的，2 是固定的，**唯一不确定的是"2000 万"这个假设**：

| 假设月用量 | 摊销成本 | 模型倍率 |
|-----------:|---------:|--------:|
| 1000 万（用得少） | $2/1M | 1.0 |
| 2000 万 | $1/1M | 0.5 |
| 4000 万（吃满配额） | $0.5/1M | 0.25 |

**用量越足，摊销越便宜，倍率越低**——这就是账号池要"喂饱"每个账号的原因。

### 实操：先估后校

1. 先填个估计值（如 0.5），跑一个月
2. 月底从 new-api 日志统计 Kiro 渠道真实 tokens，反算：
   ```
   真实倍率 = ($20 ÷ 实际1M数) ÷ 2
   ```
3. 回控制台修正

如果账号是免费渠道来的（边际成本 $0），倍率定 0.1~0.3 即可——此时它的作用不是覆盖成本，而是**价格信号**，引导用户优先走这个渠道。

## 九、综合大算例：所有倍率叠一起

王五（intern 组，分组倍率 0.5）调 claude-sonnet（模型倍率 1.5，补全倍率 5，缓存倍率 0.1）：

- 输入 3000 tokens（其中 1000 命中缓存）
- 输出 500 tokens

```
① 未缓存输入：2000 × 1.0 = 2000
② 缓存输入：  1000 × 0.1 = 100
③ 输出折算：  500 × 5   = 2500
④ 等价合计：4600
⑤ × 模型倍率：4600 × 1.5 = 6900
⑥ × 分组倍率：6900 × 0.5 = 3450 quota
⑦ 换美元：3450 ÷ 500,000 = $0.0069
```

一次调用，四个倍率各司其职：

| 倍率 | 数值 | 管什么 |
|------|-----:|--------|
| 缓存倍率 | 0.1 | 命中的输入打 1 折 |
| 补全倍率 | 5 | 输出按 5 倍折算 |
| 模型倍率 | 1.5 | sonnet 是基准价 1.5 倍 |
| 分组倍率 | 0.5 | 王五是 intern 打 5 折 |

## 十、速查卡

```
核心公式：
  quota = (输入 + 缓存输入×缓存倍率 + 输出×补全倍率) × 模型倍率 × 分组倍率
  美元  = quota ÷ 500,000

定倍率：
  模型倍率 = 官方输入价($/1M) ÷ 2
  补全倍率 = 官方输出价 ÷ 官方输入价
  分组倍率 = 自己定（定价杠杆）
  订阅制渠道 = 月费 ÷ 月用量(1M) ÷ 2

常数：
  1 USD = 500,000 quota（基准价 $2/1M 的倒数）
  1 quota = 1 个基准 token
```

## 小结

倍率体系看似复杂，拆开后只有三层逻辑：

1. **汇率层**（500,000）：one-api 定下的记账基准，1 quota = 1 基准 token，永远不变
2. **成本层**（模型倍率 + 补全倍率）：由上游官方价决定，`输入价÷2` 和 `输出价÷输入价`，照抄即可
3. **运营层**（分组倍率 + 缓存倍率）：你自己的定价杠杆，用来打折、加价、引导流量

下次在 new-api 后台看到"本次消耗 3,450 quota"，你应该能立刻心算出来：这是约 $0.007，其中多少给了输入、多少给了输出、多少是分组折扣。
