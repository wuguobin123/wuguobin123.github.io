## 为什么谈「中国模型」不能用一把尺子

很多人聊起中国大模型，第一反应是「哪个最强？」

这个问题本身就问错了。

中国大模型公司不是同一条路线赛跑，而是**完全不同路线**在跑。DeepSeek 在押效率与开源，Kimi 在押长 Context 与 Agentic，MiniMax 在押多模态与产品。每条路线的研发节奏、融资节奏、人才结构、合作伙伴都不同。

把三家按同一张 benchmark 排，就像把可口可乐、百事可乐、怪兽饮料按甜度排——其实它们想占领的是不同的胃。

## 三条路线一张图

> 它们不是同一条路线赛跑，而是三种完全不同押注。

![中国模型三条路线：DeepSeek 效率与开源、Kimi 长 Context、MiniMax 多模态](../../images/2026-07-25-ai-twelve-themes/03-china-three-routes.png)

我用一家公司一句话总结每条路线：

- **DeepSeek**：「让模型跑得更便宜」
- **Kimi**：「让模型能看更多、做更复杂的任务」
- **MiniMax**：「让模型能听能看能演」

## 路线一：DeepSeek —— 效率与开源

### 它在押什么

DeepSeek 的核心押注是**Inference Economics**（推理经济学）。

它认为：

1. 模型能力会持续商品化，毛利将来自训练成本和推理成本的结构性优势
2. 开源是分发渠道——一旦开发者跑通你的模型，切换成本就非常高
3. 中国市场对价格极度敏感，工程效率就是竞争力

### 核心技术

- **MLA（Multi-head Latent Attention）**：把 KV cache 压缩到极致，相同显存能服务更多用户
- **DeepSeekMoE**：稀疏激活，每次推理只激活部分参数
- **FP8 训练**：把训练精度从 BF16 降到 FP8，硬件成本砍半
- **DualPipe / Expert Parallel**：把训练流水线压到极限

这些不是单点魔法，是一整套「让同样的钱跑更多 token」的工程。

### 商业模式

- 通过开源权重建立开发者生态
- 接企业推理订单（API + 私有部署）
- 性价比是最大卖点

### 它放弃了什么

- 不做 Chatbot 入口
- 不做 C 端产品
- 不靠订阅收入

### 风险

- 开源模型没有用户粘性，任何人都能 fork
- 价格战下毛利持续下降
- 依赖极少数顶级研究员的产出

## 路线二：Kimi —— 长 Context 与 Agentic

### 它在押什么

Kimi（月之暗面）押的是**Context 长度 + Agent 能力**。

它认为：

1. 现实的复杂任务（读整个代码库、读完一摞财报、看完一段对话历史）需要长 Context
2. 有了长 Context，Agent 才能从「回答问题」升级到「完成多步任务」
3. Context 就是新时代的 RAM，谁控制 Context 谁就控制 Agent

### 核心技术

- **长 Context 训练**：从 200K 到 200 万 token 一路拉
- **Context 压缩与检索**：在超长 Context 里保持注意力质量
- **Browser / Tool 使用**：直接内置浏览器能力，把复杂任务下放给模型
- **Kimi Agent**：让模型从「聊天」走向「在浏览器里实际操作」

### 商业模式

- 通过 Chatbot 入口积累用户
- 探索 B 端 Agent 平台
- API 也开放，但核心是 C 端品牌

### 它放弃了什么

- 没有走极端效率路线
- 没有重投多模态
- 开源策略保守

### 风险

- 长 Context 推理成本极高，规模化困难
- Agent 落地场景还在探索，付费意愿不稳定
- 竞争激烈——DeepSeek 同样在卷长 Context

## 路线三：MiniMax —— 多模态与产品

### 它在押什么

MiniMax（MiniMax）押的是**多模态 + 内容产品 + 全球化**。

它认为：

1. 纯文本 Chat 是上一代入口，下一代入口是「能听能看能演」
2. 内容（角色、伴侣、UGC）才是 AI 落地最快的场景
3. 中国公司出海，C 端内容比 B 端 SaaS 更顺畅

### 核心技术

- **全模态模型**：文本、语音、图像、视频统一架构
- **语音合成**：自然度极高（行业内领先）
- **视频生成**：海螺 AI 是核心产品
- **角色对话**：Talkie、星野主打 AI 陪伴

### 商业模式

- C 端订阅（海螺 AI、星野）
- 内容生态（创作者分成）
- 广告与虚拟商品
- 海外市场（Talkie 主打北美）

### 它放弃了什么

- 没有押 Coding/Agent 路线
- 没有走纯开源/纯效率路线
- 不重点做企业市场

### 风险

- C 端内容受监管影响大
- 多模态推理成本极高
- 海外市场地缘政治风险
- 用户留存和付费率是核心考验

## 三条路线对比

| 维度 | DeepSeek | Kimi | MiniMax |
|---|---|---|---|
| 核心押注 | 推理效率 | 长 Context + Agent | 多模态 + 内容 |
| 关键技术 | MLA、MoE、FP8 | 200 万 Token、浏览器 | 语音、视频、角色 |
| 主要战场 | 企业推理 | C 端 Chat + Agent 平台 | C 端内容 + 海外 |
| 商业模式 | API + 私有部署 | 订阅 + 平台 | 订阅 + 内购 + 海外 |
| 开源策略 | 全面开源 | 保守 | 闭源为主 |
| 最大风险 | 价格战、毛利 | 落地速度、付费意愿 | 监管、留存、获客 |

## 关键认知

- **路线选择决定命运**：三家不是「你强我弱」，而是「你押这个我押那个」
- **效率开源、内容 Agent、模态产品** 是中国大模型当下三条主流路径
- **效率和长 Context 有内在矛盾**：长 Context 烧钱，效率路线天然不亲
- **多模态和 Coding Agent 也很难同时做**：研发资源是有限的
- **开源/闭源不是核心问题**：关键是「你能不能同时把模型、上下文、工具、用户串起来」

## 怎么判断谁是「真朋友」

作为开发者或合作伙伴，问题不是「哪家模型最强」，而是「哪家最适合这件事」：

- **做企业内部推理、私有部署** → DeepSeek 系生态最完善
- **做长文档分析、知识库、Agent 平台** → Kimi 长 Context 优势仍在
- **做陪伴、内容、虚拟人、全球化产品** → MiniMax 多模态体验最好
- **不确定** → 先用 API 跑 benchmark，别赌单一供应商

## 一些反直觉的观察

1. **DeepSeek 的「开源」其实是反向营销**：开源本身不赚钱，它赚的是「开发者都在用我的格式」这件事的网络效应
2. **Kimi 的 200 万 Context 不一定对你有用**：很多 200 万 Context 的调用，实际有效信息集中在前 5 万 token
3. **MiniMax 的护城河可能是「声音」**：语音合成技术是中国少数能在全球领先的方向
4. **路线一旦选了，迁移成本极高**：每条路线的人才结构、合作伙伴、组织文化都不同，3 年内换路基本等于重新创业
5. **同一个 benchmark 看三家是误导**：Coding 评测、Chat 评测、视频评测，三家强弱完全反过来

## 观察指标

- API 价格的下降曲线（看谁在打价格战）
- 开源模型的下载量与 fork 数（看 DeepSeek 生态）
- 长 Context 业务使用量（看 Kimi 落地速度）
- C 端产品 DAU、留存、付费率（看 MiniMax）
- 多模态产品的国际市场份额（看 MiniMax 出海）
- 顶级研究员流动（看组织稳定性）
